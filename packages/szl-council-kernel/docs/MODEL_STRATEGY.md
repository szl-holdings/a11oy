# Council model strategy

## Recommendation

Do not train one sovereign council model as the authority. Build a versioned specialist family behind the deterministic kernel.

## Candidate models

| Model | Function | Promotion metric |
|---|---|---|
| Governor/router | selects depth, tools, models, and escalation | verified outcome per cost/latency |
| Sentinel | injection, bypass, exfiltration, unsafe ambiguity | attack recall at bounded false blocks |
| Verifier | compiles claims into objective probes | false-green rate and proof completeness |
| Value | forecasts cost, utility, delay, opportunity cost | realized-vs-forecast calibration |
| State codec | portable structured state | replay fidelity with no private reasoning |
| Drift sentinel | model/tool/policy/data drift | detection delay and false alarms |
| Domain adapters | legal, maritime, security, real estate, revenue | domain benchmark and outcome closure |

## Training corpus requirements

Use only owned, licensed, or permissioned data with a signed manifest. Favor structured claims, policy decisions, verifier results, adversarial traces, branch outcomes, rollback outcomes, and delayed value settlements. Exclude secrets, private chain-of-thought, unauthorized customer content, and unlicensed repository text.

## Baselines

Compare against strongest single model, self-consistency, standard Mixture-of-Agents, Self-MoA, debate, orchestrator/judge, and a deterministic policy-only baseline. Normalize by cost, latency, and verifier coverage.

## Promotion

Every candidate requires lineage, rights, reproducible training, contamination checks, red-team evaluation, calibration, cost/latency profile, rollback-compatible package, Fourfold promotion result, and transparency receipt.
