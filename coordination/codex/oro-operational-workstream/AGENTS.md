# AGENTS.md — ORO operational workstream

This file narrows the root `AGENTS.md` for work under this directory. The root doctrine remains authoritative.

## Mission

Turn ORO — Obligation-Ranked Orbits — into protected, runtime-backed A11oy functionality with independent Lean evidence. This is a coordination lane, not production source. Permanent implementation belongs in normal runtime, test, schema, migration, documentation, Dockerfile, and Lean paths on separate protected branches.

## Non-negotiable laws

1. **Rank Law:** every loop-closing transition must strictly decrease the reviewed lexicographic rank. Fan-out must partition inherited authority and budget; no child may mint rank.
2. **Codex Law:** global invariants run only after reducers merge at a deterministic barrier. Invariant implementations are protected local code selected by a signed data manifest; remote code is never executed.
3. **Disposition Law:** an orbit may propose changes to prompts, tools, routing, and isolated candidates. It may not rewrite its kernel, rank function, Codex, evaluator, proof binder, release policy, or protected governance.

## Honesty boundary

- Runtime-enforced behavior may be labeled `MEASURED` only after protected CI and runtime readback.
- Well-founded termination remains `MODELED` until the exact Lean theorem compiles on protected `lutar-lean/main` with `--no-sorries` and the immutable evidence is bound back into A11oy.
- Global action optimality, unrestricted self-improvement, Byzantine consensus, and general causal identification are not claimed.
- A blocked or refused transition is a valid result. Never convert missing evidence into green.

## Delivery topology

Codex must produce three permanent PRs:

1. `szl-holdings/a11oy`: runtime, APIs, dashboards, schemas, migrations, Docker wiring, adversarial tests, and one narrow read-only demonstration.
2. `szl-holdings/lutar-lean`: rank and finite-basis negative-space witnesses, built by the pinned Lean toolchain with `--no-sorries`.
3. `szl-holdings/a11oy`: a data-only proof-binding PR created only after the Lean PR merges and its protected evidence artifact is verified.

This coordination PR remains draft and must close without merge after the permanent PRs exist.

## Forbidden operations

- no direct push to protected `main`;
- no force update, history rewrite, administrator merge, fake status, required-check removal, or ruleset weakening;
- no secret-value readback or serialization;
- no self-review, self-approval, self-merge, or candidate-written evaluator;
- no external production write in the demonstration;
- no floating-point monetary persistence;
- no arbitrary callable loaded from a remote Codex manifest;
- no proof promotion from source inspection alone.

## Work discipline

Audit → smallest falsifiable plan → isolated implementation → tests → adversarial replay → security/provenance review → protected PR → merge queue → live readback → immutable receipt.

Update `STATUS.md` after every material transition. Every status must contain exact repository, branch, head SHA, check state, evidence artifact, blocker, and next action. Do not mark a phase complete from intentions or local-only evidence.
