# Source-owned Lyte publication transaction

The existing A11oy publisher owns the Lyte projection on Hugging Face. Its
focused `lyte` workflow input preserves sibling Spaces. The manual publisher,
the opt-in canonical vertical job and the canonical Finance projection share
`hf-vertical-estate` job concurrency
through publication, source binding, restart and verification. They do not
cancel an in-flight writer. The canonical product deployment retains its
independent lifecycle.

The source plan resolves a verified current `lyte-services` main commit, checks
all 17 required source checks from GitHub Actions app 15368, and retrieves the
complete native source workflow run and latest attempt's jobs. The existing
`szl_release_guard.source_qualification` validates the bound repository, source,
workflow, run, attempt and jobs. Source CI does not establish a live application
or production qualification.

An exact temporary checkout contains the producer's tracked
`source_revision.txt`, which may be `UNAVAILABLE`. The writer retains that file's
original digest and removes only that marker in the isolated checkout. The
byte-pinned controller generates the admitted revision through its existing
`--source-revision-file` contract. The generated marker is a declared publication
projection, rather than a claim that every projected file equals a tracked Git
blob. The dry-run derives the complete Docker closure and a stable manifest
digest before any Hub configuration or publication write.

The prepared plan binds producer and publisher revisions, controller revision
and blob, application version, destination, generated marker, manifest digest,
existing HF parent and one operation ID. Immediately before publication the
writer rechecks both producer and publisher main tips. The controller uses
provider `parent_commit` compare-and-set and retains its durable intent before
submitting the commit. Publication is submitted once. A commit acknowledgement
and current target readback must match the prepared plan before the runtime
source variable changes. Variable metadata is read back independently. The
writer then restarts, attests immutable bytes and the running revision, verifies
the semantic Lyte contract, and rechecks source and target once more.

The existing `ReleaseJournal` records each phase and its evidence digest on
disk. The workflow uploads its complete evidence directory on terminal runs.
This event chain is unsigned local evidence; it is neither an independent
review nor an external immutable journal. The prior HF parent is retained as a
rollback candidate, with runtime rollback acceptance explicitly `UNVERIFIED`.
No automatic rollback, paid hardware change or model admission is introduced.

A newer producer, publisher or HF target returns `SUPERSEDED`. A publish, source
binding or restart whose outcome is unknown returns `OUTCOME_UNCERTAIN`; later
mutations stop. The retained controller intent must be reconciled through the
same pinned controller's read-only `--reconcile-transaction` command before a
retry is considered. Reconciliation checks the operation marker, expected
parent, immutable file closure and remote current state. Cross-provider atomicity
and exactly-once side effects are not asserted.

All subprocess execution, including controller download, uses the existing
POSIX bounded runner. It caps combined stdout/stderr, enforces a wall-clock
deadline and kills the process group on timeout or output exhaustion. The
controller download rejects redirects and excessive bodies and verifies its
Git blob. Public failure receipts retain reason codes, types and output digests;
arbitrary provider errors, token values and presigned URLs are omitted.

Tests execute the actual pinned controller CLI against fixture source, verify
the generated marker and stable manifest through repeated derivation, and
exercise failures before and after every mutation boundary. Linux CI also
exercises a hanging descendant and an output flood through the real runner.
These are offline integration tests. Live publication, runtime/browser journeys,
production storage acceptance and provider quality require separate evidence.

The controller is pinned to the protected merge of
[the controller transaction change](https://github.com/szl-holdings/.github/pull/808),
`163a61fd9759e5ecc3c2daf13e528f7b281ff81d`, with independently verified Git blob
`3fa968416a3623d66b5b5b64abf8b830cc854e1c`. Its protected source acceptance and
offline CLI proof do not establish publication or runtime acceptance.
