# Governed Real Data Gateway — initial release gates

The initial release must satisfy the following in one exact source lineage.

1. The canonical Hugging Face publisher observes the mobile page, registry, health route, and Lyte evidence envelope before runtime configuration proceeds.
2. The post-deployment verifier checks out current protected `main`, then requires it to equal the deployment workflow SHA. Event-controlled code is never checked out into the proof job.
3. The registry exposes exactly six governed verticals and the fixed provider authorities.
4. Each vertical returns `LIVE`, `CACHED`, or `UNAVAILABLE`; an unavailable provider cannot return data.
5. At least one official/provider-operated source must return observed current or cached evidence before the release is called operational.
6. Every envelope keeps `external_writes=DISABLED`, `effectors=[]`, `production_authorization=false`, and `automatic_remediation=false`.
7. The responsive developer surface must pass phone, tablet, desktop, high-zoom, keyboard, reduced-motion, contrast, and technical-text containment contracts.
8. The exact protected head must have no failed checks, no pending checks other than its own promotion gate, no change request, and no unresolved review thread.
