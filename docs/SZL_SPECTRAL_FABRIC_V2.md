# SZL Spectral Fabric v2

## Purpose

Spectral Fabric is the shared experience layer for the SZL Holdings public estate. It makes the websites and applications feel unmistakably related without making them look cloned.

The product origin remains an operational command environment. The proof origin remains an independent evidence environment. Each vertical, route, and Hugging Face Space receives its own instrument identity, geometry, rhythm, and accent behavior while preserving a common interaction grammar.

## Design synthesis

The system combines six useful design disciplines and translates them into original SZL implementation:

1. **Editorial restraint** — clear hierarchy, generous space, direct copy, and fewer competing calls to action.
2. **Mission framing** — cinematic depth and strong product narratives that explain what an operator can accomplish.
3. **Accelerated-compute energy** — luminous technical geometry, responsive depth, and a sense of active computation.
4. **Operational observability** — dense but legible telemetry, progressive disclosure, and fast movement between entities.
5. **Visible procedures** — actions, stages, handoffs, and proof states presented as understandable sequences.
6. **Business-state storytelling** — connect signals and decisions to outcomes rather than presenting vanity metrics.

No third-party code, images, logos, layouts, or trade dress are copied. The implementation uses the KANCHAY palette, SZL doctrine, local assets, first-party route semantics, and original geometry.

## Holographic behavior

Spectral Fabric adds a local DOM/CSS field composed of six independent layers:

- perspective mesh;
- route-specific orbit;
- evidence or topology nodes;
- refracted light beam;
- restrained scan plane;
- pointer-responsive bloom.

Pointer movement and scroll depth update CSS variables through one request-animation-frame scheduler. There is no continuous JavaScript render loop. Existing WebGL experiences, including the real-data A11oy proof lattice, remain product-owned and are not replaced.

## Performance tiers

The client selects an experience tier without transmitting device information:

- **Full** — all layers and responsive depth on capable desktop devices.
- **Balanced** — reduced layer count and opacity on mobile or constrained hardware.
- **Quiet** — static bloom and beam for reduced-motion, data-saver, or low-resource devices.

The decision uses only local browser signals. It is not stored, logged, or sent anywhere.

## Accessibility contract

- 44-pixel minimum interactive targets;
- visible keyboard focus;
- Escape closes mobile navigation;
- safe-area-aware placement;
- reduced-motion, increased-contrast, forced-colors, and print fallbacks;
- no content hidden behind animation;
- no required hover interaction;
- no horizontal page overflow introduced by the shell.

## Truth boundary

The holographic field is presentation only. It never invents telemetry, receipts, model quality, deployment state, or operational readiness. Data-driven graphics must continue to bind to their existing measured sources and honest unavailable states.

## Rollout sequence

1. Merge the product-origin assets through protected CI.
2. Confirm source-bound deployment and verify the public product routes.
3. Merge the complementary proof-origin treatment while preserving zero-JavaScript evidence pages.
4. Promote source-native adapters to supported Space repositories through reviewable pull requests.
5. Verify each deployed Space at mobile and desktop widths and retain any unsupported application as an explicit exception rather than applying a destructive generic rewrite.
